# 자동 실험과 회귀 검증 구현

## 구현 순서

1. unit verification naming rule을 정한다.
2. 공통 tolerance와 compare helper를 만든다.
3. scenario 구조를 정의한다.
4. `Simulink.SimulationInput` 생성 함수를 만든다.
5. 한 scenario 실행과 result extraction을 만든다.
6. metric 계산과 pass/fail 판정을 만든다.
7. 여러 seed 반복과 summary table을 만든다.
8. baseline 결과와 새 결과를 비교한다.
9. Markdown용 결과 요약을 생성하거나 수동 기록한다.

## 예정 파일

```text
src/+amr/+verification/computePoseMetrics.m
src/+amr/+verification/computeMapMetrics.m
src/+amr/+verification/computeNavigationMetrics.m
src/+amr/+verification/evaluateMission.m
scripts/run_amr_scenario.m
scripts/run_all_amr_scenarios.m
tests/unit/verify_*.m
tests/scenarios/verify_normal_delivery.m
tests/scenarios/verify_obstacle_recovery.m
tests/scenarios/verify_sensor_timeout.m
```

## 기본 시나리오 세트

1. 정상 배송
2. 목표점 도달 불가
3. 동적 장애물 일시 정지
4. 동적 장애물 장기 차단
5. LiDAR dropout
6. encoder slip
7. localization invalid
8. local planner no candidate
9. emergency stop
10. battery return-to-home

## 실패 처리

여러 시나리오를 실행할 때 한 시나리오 실패로 전체 결과가 사라지지 않도록 각 결과와 오류 원문을 별도로 저장한다. 최종 summary에서 실패 개수와 reason을 표시한다.
