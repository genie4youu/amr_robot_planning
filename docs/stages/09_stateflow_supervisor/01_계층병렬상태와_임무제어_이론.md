# 계층·병렬 상태와 임무 제어 이론

## 역할 경계

Stateflow가 담당하는 것:

- 무엇을 해야 하는가
- 어느 목표로 가야 하는가
- 언제 취소·재시도·복구할 것인가
- 언제 감속·정지·임무 중단할 것인가

Stateflow에 넣지 않는 것:

- A* search
- scan matching
- DWA trajectory rollout
- 연속 plant dynamics

## 추천 계층

```text
PoweredOff
Initializing
Operational
├─ Mission
│  ├─ Idle
│  ├─ GoToPickup
│  ├─ Loading
│  ├─ GoToDropoff
│  ├─ Unloading
│  └─ ReturnHome
├─ Navigation
│  ├─ Inactive
│  ├─ Planning
│  ├─ Following
│  └─ Recovering
└─ Health
   ├─ Healthy
   ├─ Degraded
   └─ Fault
```

Mission, Navigation, Health는 병렬 region 후보지만, 공유 데이터를 쓸 때 execution order와 단일 writer 원칙을 지켜야 한다.

## 전이 설계

- transition마다 trigger, guard, action을 구분한다.
- retry 횟수와 timeout을 명시한다.
- entry action에서 일회성 요청을 생성한다.
- during action에서 요청을 반복 생성하지 않도록 한다.
- emergency와 fault transition은 상위 계층에서 공통 처리한다.

## Temporal logic

- `after`: 상태 timeout
- `duration`: fault condition이 일정 시간 유지되는지 확인
- debounce: 순간 glitch 제거
- hysteresis: threshold 근처 상태 왕복 방지
