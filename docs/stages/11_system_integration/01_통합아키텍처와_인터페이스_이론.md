# 통합 아키텍처와 인터페이스 이론

## 최상위 subsystem

```text
Scenario and Environment
Robot Plant
Sensors
Mapping and Localization
Global Navigation
Local Navigation and Control
Safety Monitor
Stateflow Mission Supervisor
Visualization and Logging
```

## 통합 원칙

- subsystem은 명시된 입력만 읽고 출력만 쓴다.
- 같은 의미의 신호를 여러 이름으로 복제하지 않는다.
- Stateflow와 수치 알고리즘 사이에는 request/status 계약을 둔다.
- valid가 false인 데이터의 값은 사용하지 않는다.
- 초기화되지 않은 map이나 pose로 planner를 실행하지 않는다.
- 최종 plant command의 writer는 safety arbitration 하나뿐이다.

## Mode

최소 mode:

- `SimulationReset`
- `Mapping`
- `LocalizationInit`
- `Delivery`
- `Recovery`
- `EmergencyStop`

mapping mode와 delivery mode에서 지도 갱신 정책이 다르다는 점을 명시한다.

## 초기화 순서

1. parameter와 map metadata
2. plant state
3. sensor state와 timestamp
4. map/localization
5. planners/controllers
6. Stateflow supervisor
7. logging

## Multirate

통합 전에 subsystem별 sample time과 data age limit를 표로 만든다. 다른 rate 사이의 전달은 zero-order hold, Rate Transition, event/enable 중 하나를 의도적으로 선택한다.

## Variant 전략

초기 통합은 복잡도를 줄이기 위해 기능을 교체할 수 있게 한다.

- pose source: ground truth / odometry / localization
- controller: Pure Pursuit / DWA
- map source: reference / built map
- fault injection: off / selected fault
