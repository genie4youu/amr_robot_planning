# AMR 다중환경 강건성 행렬

관련 프롬프트: [[2026-07-23_AMR_다중환경_자동진행]]

## 범위

- 실제 특정 시설을 복제하지 않은 자체 합성 사무실, 병원 중앙 복도, 물류 창고 랙 지도
- normal, obstacle, battery, wrong-turn 네 상황
- 동일한 LiDAR, A*, local costmap, DWA, safety gate, Stateflow 제어 구조 재사용
- range noise, beam/frame dropout, 1-sample delay와 scan freshness watchdog

## 구현

- `createEnvironmentFloorMap`: 세 환경의 벽, 고정/동적 장애물, start/goal/charger 정의와 A* 기준 경로 생성
- scenario code `1..12`: 환경과 상황을 기존 Simulink 입력 하나에 인코딩
- UI 환경 드롭다운과 환경 변경 시 지도 재생성
- log-odds inverse range sensor mapping prototype
- pose EKF covariance와 localization health prototype

## 검증 결과

- floor-map 연결성/경로 비충돌 3/3 PASS
- 알고리즘 단위검사 4/4 PASS
- Scenario Lab 환경 행렬 12/12 PASS
- Integrated Plant/Industrial Supervisor 환경 행렬 12/12 PASS
- 두 Simulink 모델 구조 검사: unconnected port/line 없음, Stateflow lint healthy
- 모든 주행 조합 최종 위치 오차 약 `0.080 m` 이하

## 발견하고 수정한 문제

- 창고 동적 장애물이 기준 경로에서 너무 멀어 센서/회피를 충분히 자극하지 않아 경로 가까이 재배치했다.
- frame dropout hold 상태를 매 simulation sample마다 세던 보고값을 연속 구간의 상승 edge만 세도록 수정했다.
- `exportapp`가 UIAxes를 빈 영역으로 저장하는 현상을 확인해 UI snapshot을 `getframe` + `imwrite` 방식으로 변경했다.

## 남은 제한

- 지도는 실제 측량 도면이 아닌 실무형 합성 layout이다.
- global A*의 동적 장애물은 known rectangle이며 local DWA만 scan-derived hit를 사용한다.
- log-odds mapping과 EKF health는 독립 prototype으로, 아직 주행 Plant/Supervisor에 연결하지 않았다.
- 실제 SLAM scan matching, loop closure, pose graph와 실제 센서/HIL은 미구현이다.
